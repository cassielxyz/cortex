# Cortex UI Quality

## Route before designing

Choose only what the task needs:

1. `cortex-ui-ux-pro-max` — UX, layout, platform and design-system decisions.
2. `cortex-taste` — hierarchy, typography, spacing, restraint and anti-generic art direction.
3. `cortex-awesome-design` — design-direction references when useful.
4. `cortex-21st-ui-explore` — meaningfully different UI directions when the direction is not settled.
5. ThreeUI Community / threeui.com — Three.js heroes, shaders, motion and spatial component references for cinematic/3D work.
6. `cortex-cinematic-web` — 2.5D, video-scrub, Three.js/R3F or cinematic scroll tasks.
7. `cortex-image-to-code` — only when an approved screenshot/reference must be translated faithfully.
8. `cortex-web-design-guidelines` + `cortex-21st-ui-review` — implementation review.
9. `cortex-playwright` — actual browser inspection.

Do not copy another site's identity or proprietary assets. References are for layout, motion grammar, hierarchy, material language and interaction principles.

## Visual-first workflow

```text
understand subject
→ inspect current UI/assets
→ choose visual architecture
→ gather 2–4 relevant references
→ define art direction + exclusions
→ implement one strong direction
→ browser inspect
→ capture desktop/mobile screenshots
→ compare to request/references
→ repair
→ repeat until material gaps are gone
```

For real products or recognizable subjects, verify fidelity before polish. A beautiful page with the wrong subject is a failed page.

## Avoid generic AI UI

Do not default to:
- giant all-caps headings everywhere;
- repetitive dark glass cards;
- neon cyan/purple gradients;
- arbitrary glow pills and badges;
- random geometric backgrounds;
- too many navbar items;
- every section using the same card grid;
- decorative motion that does not explain or reveal anything;
- fake 3D objects when authentic product assets are required.

Prefer:
- fewer but stronger compositions;
- editorial spacing;
- product-first negative space;
- intentional type scale;
- one dominant accent;
- coherent motion grammar;
- content density appropriate to the product;
- real imagery/3D assets carrying the visual identity.

## ThreeUI and 21st.dev usage

ThreeUI is a reference/component library, not a design style. Search it only when the task benefits from a Three.js/WebGL interaction. Prefer free Community source and adapt it to the project's visual language.

21st.dev is strongest for the DOM/UI layer. Use its explore/search/review workflows for components, interface directions and critique, but keep cinematic stages and WebGL scenes under the selected visual architecture rather than surrounding them with generic component cards.

## Required UI evidence

Check:
- desktop and narrow/mobile layouts;
- overflow and safe areas;
- typography and contrast;
- focus/keyboard states;
- loading/empty/error states;
- hover/active/disabled states;
- image/model/video failure states;
- console/network failures;
- core interactions;
- slow/fast/reverse scroll for scroll-driven pages;
- screenshot evidence after the latest meaningful visual change.

A compile-only pass is not UI verification. A screenshot is not enough by itself either: inspect it, compare it to the request/reference, repair the largest visible mismatch, and capture again.
